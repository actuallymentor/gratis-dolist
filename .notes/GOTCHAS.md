# Gotchas

- User values calm UI: never put syntax legends/queries/toggles on the main surface; hide behind one quiet control.
- Mobile tap cost matters: avoid symbols beyond the iOS 123 layer (`# { } % *` are deep on iOS).
- New review round → new db collection (feedbackN) so old marks don't mix.
- Prototype popovers: handlers that re-render the pop must survive the document "click outside" listener (detached targets) and blur-on-remove re-entrancy. Verify with puppeteer-core + /usr/bin/google-chrome (playwright module absent); install puppeteer-core in scratchpad.
- Deploys: only via GH Actions (push to main). Local remote is SSH but no key in container → push with `gh auth setup-git` + https URL. Site currently = design prototype wrapped by scripts/build.mjs.
- Waiting on a process: never `until ! pgrep -f "X"` when X appears in the loop's own cmdline (self-match → infinite loop). Use `pgrep -x` / match `[c]odex exec`.
- `pkill -f "X"` inside a Bash call whose own command line also contains X kills the calling shell (exit 144). Kill by PID, or keep X out of the same command.
- npm workspaces: `vitest`/`eslint` run from root; spikes/ excluded from both on purpose.
- TinyBase: stock IndexedDB persister rewrites the whole store per save (~230 ms at 10k) → use `spikes/sync/src/idb-incremental.js` pattern. `load()`+`startAutoSave()`, never `startAutoPersisting()` (1 s full re-read). Bulk `setContent` of 10k freezes 4 s → batch imports.
- TinyBase skew guard (5 min) silently drops ALL edits from a fast-clock device, then later they overwrite newer edits → stamp with server-offset time.
- Acks must wait for `flush()` (apps/web/src/modules/dolist.js): an IDB write aborted by navigation within ms is lost. Toasts/draft-clear happen after commit.
- TinyBase `persister.schedule()` with no args throws on an empty queue; wait for persister status idle (store's `flush()` does).
- Lint `--fix` rewrites files mid-session → harness reports "changed on disk"; check `git diff` before assuming another agent touched it.
- TinyBase persisters swallow load/save errors (tryCatch → onIgnoredError; status still goes Idle). Store wraps get/set_persisted to record them: failed load → `ready` rejects, no autosave; failed save → `flush()` rejects + `on_save_error`. Full save without a successful load merges, never clears.
- `describe.skipIf` still runs the suite callback at collection: never read gitignored fixtures there unguarded.

- **Edit buffers must follow the store.** A local `useState(task.x)` committed on close overwrites other tabs' newer edits. Use a buffer with a base (TaskDetail `use_field`): adopt stored changes unless the user holds an edit; settle after save.
- **sessionStorage is copied** into duplicated / `window.open` tabs → "per-tab" ids collide. Verify uniqueness with a Web Lock `ifAvailable` (retry once for reload races); buffer draft writes in memory until the id is final.
- **A failed IDB write loses its delta.** Incremental persister sets `repair_pending`; the next save merges full content. Don't just clear the error.
- **wrangler dev rewrites request URL + Origin to the route host** (`http://dolist.gratis.sh`). Never gate on hostname; e2e tenant switch is gated by the `E2E` var only (unit test forbids it in configs).
- **wrangler dev loads `.env.local` into the Worker** (incl. TODOIST token). Playwright sets `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false`.
- **Offline WebSockets:** Chromium emulated offline stalls (no close), WebKit keeps it alive; `close()` while offline hangs on the handshake. Client detaches the socket on `offline` before closing.
- **TinyBase WsServerDurableObject:** overriding `authorize` switches to hub mode; access object is the socket attachment (survives hibernation). Revocation needs a stored fence, not only closing sockets.
- **Playwright browsers can vanish from ~/.cache** → `npx playwright install chromium webkit`.
- **TinyBase `startSync()` resolves even when the exchange timed out**; errors only reach `onIgnoredError`. Never treat resolve as "synced".
- **TinyBase skew guard drops edits silently** and HLCs are monotonic, so one fast-clock stamp poisons all later edits. Dolist runs with `Infinity`.
- **`pgrep -f "x"` in a `while` loop matches its own shell** → loop never ends. Wait on explicit PIDs.
- **codex reviews get cut off by OpenAI's cyber filter** when prompts say "security holes"; frame as correctness/reliability.
- **iOS won't raise the keyboard on autofocus** without a user gesture; /capture focuses the input (caret ready) but the tap-to-type remains on iOS. Real-device check pending.
- **Floating pills cover mobile content** (bottom-left sits on lists/details). Keep persistent hints inline (Settings), pills only for transient actions.
- **Idempotency beats per-tab guards.** Shares get a content-derived task id (`share-<fnv>`), so retries, history and cloned tabs can't duplicate. Re-adding rewrites the row (reopens a completed one).
- **A retry with unchanged data never triggers autosave.** `flush()` forces a repair save when the persister has a failed write pending.
- **WebKit e2e stall under load:** with 8 parallel workers, ~1 run in 5 a WebKit `/api/login` POST to wrangler dev never completes (absent from the trace's network log, which only lists finished requests). Never alone (12/12), never Chromium. iphone project has `retries: 1`. Fixed along the way: leaked test contexts (close in afterEach), `add()` waits for the durable ack, 3 MB test in its own `heavy` project, local workers 8.
- **Passkeys need a domain RP id**: never derive it from the request (wrangler dev rewrites URLs); `ORIGIN` var (prod in wrangler.jsonc, e2e `--var ORIGIN:http://localhost:8787`). 127.0.0.1 can't be an RP id → e2e must browse `localhost`.
- e2e mail: `/api/e2e/outbox` (E2E only). Read it only after the UI says "Sent to …" or the race returns null.
- Playwright hooks in an imported helper register only for the first spec a worker loads → export `close_devices`, call `test.afterEach` per spec.
- WebKit ↔ wrangler dev stall reproduces with bursts of sequential POSTs (6 code attempts): a request just never completes, even serially. Not seen on Chromium. Server-only rules → test on Chromium only.
- `useEffect( () => cond && promise )` / `return promise` inside an effect = React treats it as cleanup → blank page. Never return a promise from an effect.
- Global keys (`use_shortcuts`) bail while any `[role="dialog"]` exists; new overlays must carry that role or j/k/e act behind them. e2e: wait for the page heading before pressing keys (store loads async, Overlays mount after).
- Modal opener focus must be captured at render (`useState` init): child `autoFocus` runs before effects, so an effect sees the dialog's own input.
- Edited titles carry stored `literal_mask` by substring match (TaskDetail `carry_masks`); without it, quoted text from capture parses on the next edit.
